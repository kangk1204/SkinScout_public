# 인덱스 밖 표적을 채우는 계획

SkinScout의 표적 순위와 표적 검색은 ChEMBL 37 + BindingDB 측정 기록(표적 4,873개)을
읽는다. 그런데 피부 효능 표적으로 자주 쓰이는 계열 — 사이토카인, 성장인자, 전사인자,
그리고 TEWL·세라마이드·히알루론산 같은 **비단백질 종료점** — 은 이 인덱스 밖인 경우가
많다. 사용자 리스트에서도 이 계열이 조회 불가로 남았다.

이 문서는 그 공백을 어떤 순서로, 어떤 근거와 라이선스로 채울지 정한다. 지금은 계획만
두고 데이터는 넣지 않는다 — 표적 하나를 추가하는 일은 채점기를 바꾸는 일이므로,
측정과 게이트가 따라오지 않으면 넣지 않는다.

## 공백의 종류를 먼저 나눈다

| 종류 | 예 | 지금 상태 | 채우는 방법 |
|---|---|---|---|
| 리간드가 드문 단백질 | 사이토카인·성장인자·전사인자 | 인덱스 밖 | 문헌·특허 활성 측정 추가, 또는 도킹 가설 경로(근거 약함 표시) |
| 리간드는 있으나 DB 밖 | 최근 특허 물질 | 인덱스 밖 | BindingDB/특허 큐레이션으로 evidence 추가 |
| 비단백질 종료점 | TEWL, 세라마이드, HA, 산화 DNA 부가물 | 표적이 아님 | 표적 검색이 아니라 **효능 근거 주석** 계층으로 다룬다 |

## 채우는 순서

1. **있는 것부터 켠다 (설정 한 줄).** GtoPdb 티어는 이미 별도 인덱스로 만들어 두었다
   (`data/activity_retrieval_runtime_gtopdb_202608`). 기본값에서 뺀 이유는 ODbL/CC BY-SA
   share-alike이기 때문이고, 결과를 공개 배포하지 않는 분석에서는 `daina_recipe_index_dir`
   한 줄로 켤 수 있다. 다만 실측으로 공백 표적 대부분은 GtoPdb에도 없다 — 이 단계는
   비용이 낮으니 먼저 시도하고, 얻는 표적 수를 기록한다.
2. **문헌·특허 evidence 추가.** `scripts/build_bindingdb_temporal_evidence.py`와
   ChEMBL evidence 빌더가 읽는 것과 같은 스키마(`uniprot, smiles, pactivity, endpoint,
   source`, `publication_key`)로 새 evidence parquet을 만든다. 표적별로:
   - 1차 문헌에서 화합물–표적 활성값을 사람이 확인하고 `publication_key`를 남긴다.
   - 특허 물질은 BindingDB에 이미 있는 경우가 많으니 먼저 검색한다.
   - 행마다 출처와 라이선스를 기록한다. 재배포 제한 자료는 **기본 인덱스에 넣지 않는다**
     (LICENSE_POLICY.md의 원칙과 같다).
3. **구조 기반 가설 경로(마지막 수단).** 리간드가 정말 없으면 도킹·PSICHIC을 쓸 수 있지만,
   이 저장소가 측정한 바로는 도킹 단독 순위는 무작위와 구분되지 않았다. 그래서 이 경로는
   순위가 아니라 `가설(측정 근거 없음)` 라벨로만 내보내고, 대체소재·표적 순위와 섞지 않는다.
4. **비단백질 종료점은 따로.** TEWL·세라마이드·HA 같은 것은 표적이 아니라 효능 지표다.
   이미 있는 피부 효능 KG 라벨(`kg_efficacy_label`)과 임상 종료점 주석을 확장하는 쪽이 맞고,
   표적 검색 인덱스에 억지로 넣지 않는다.

## 넣을 때 지키는 것

- **게이트**: evidence를 추가하면 `scripts/validate_activity_retrieval_gate.py`로 인덱스와
  게이트를 다시 만든다. 표적 수·판정이 바뀌면 결과 매니페스트도 다시 만든다.
- **측정**: 표적을 추가하는 목적이 "그 표적을 채점할 수 있나"라면, 정답표(known panel)에
  양성 쌍을 함께 넣고 회수율을 잰다. 측정 없이 추가하지 않는다.
- **라이선스**: share-alike 자료는 기본 경로에서 제외한다. 켜는 순간 결과물 전체에
  의무가 따라온다는 사실을 문서와 화면에 남긴다.
- **공개 경계**: 공개 스냅샷에는 데이터가 실리지 않는다(빌드 산출물). 계획과 스키마만
  공개되고, 채운 데이터는 각자 원천에서 다시 만든다.

## 규모 추정

| 작업 | 내용 | 대략 |
|---|---|---|
| GtoPdb 티어 실험 | 설정 한 줄, 표적 수 비교 | 0.5일 |
| 표적 10개 문헌 evidence | 표적당 활성 20–50행 큐레이션 + 스키마 검증 | 1–2주 |
| 인덱스·게이트 재빌드 | 빌더 실행과 게이트 재판정 | 1일 |
| 정답표 확장·측정 | 양성 쌍 추가, 회수율 재측정 | 2–3일 |
| 비단백질 종료점 설계 | KG/주석 계층 확장 설계 | 별도 과제 |
