# Workbench 사용성 업그레이드 — 입력·출력·시각화·접속

- 작성일: 2026-08-28 (Asia/Seoul)
- 선행: `docs/P0_TRUST_FIXES_20260828.md` (화면이 사실과 다르게 말하던 것들)
- 범위: 연구자가 실제로 쓰는 루프 — 무엇을 넣고, 진행을 어떻게 보고, 결과를
  어떻게 읽고 가져가고, 다른 컴퓨터에서 어떻게 접속하는가

각 항목은 **실제 브라우저(headless Chrome)** 로 검증했다. 정적 검사로는 잡히지 않는
결함을 브라우저 검사가 세 건 잡았고, 그 내용도 함께 적는다.

## 1. 입력 — 이름으로 찾고, 넣자마자 구조를 본다

### 이전

SMILES 문자열 또는 SDF 파일. 그게 전부였다. SMILES를 모르면 PubChem에 가서 찾아와야
했고, 오타로 다른 분자가 들어가도 **수 시간짜리 실행이 끝나야** 알 수 있었다.
적용범위 판정은 제출 핸들러 안에서만 돌았고, 물성 경고는 계산해 놓고 **버렸다**.

### 지금

**이름으로 찾기** — `나이아신아마이드`, `Retinol`, `caffeine` 처럼 입력하면 후보가
뜨고 누르면 SMILES가 채워진다.

색인은 오프라인으로 만든다(`scripts/build_compound_name_index.py`).

| 단계 | 수치 |
|---|---|
| CosIng INCI 이름 | 36,834개 (정규화 후 고유) |
| 별칭 테이블과 일치 | 1,674개 → 화합물 1,443개 |
| 그 화합물들의 모든 별칭 | 17,761개 |
| 한국어 큐레이션 별칭 | 34개 |
| 파일 크기 | 1.9 MB |

일치율이 4.5%인 것은 CosIng 대부분이 추출물·혼합물·고분자이기 때문이고, 그것들은
어차피 **적용범위 밖**이다. 남는 1,443개가 이 도구가 다룰 수 있는 단일 저분자다.

한국어는 별도 큐레이션(`data/compound_names/korean_aliases.csv`)이다. 상류 별칭
테이블에 한국어가 없다. 만들면서 정규화 함수가 `[^a-z0-9]`로 되어 있어 **한글을
통째로 지우고 있었다** — 유니코드 `\w`로 고쳤다.

**넣자마자 구조가 보인다** — `POST /api/compound/preview`가 RDKit이 실제로 읽은
분자의 2D 그림, 정규 SMILES, InChIKey, 분자식, 적용범위 판정, 그리고 지금까지
버려지던 물성 경고 10종을 돌려준다.

브라우저 실측(4개 입력):

| 입력 | 판정 | 그림 | 시작 버튼 |
|---|---|---|---|
| 아스피린 | 분석 가능 | 36 path | 활성 |
| 에탄올 | 분석 가능 (확인 필요) + 경고 2건 | 6 path | 활성 |
| 트리펩타이드 | **분석할 수 없음** (펩타이드) | 57 path | **비활성** |
| `C1CC1))(` | **구조를 읽지 못했습니다** | — | **비활성** |

물성 경고는 실행을 막지 않는다. 검증 패널(15화합물) 범위 밖이라는 사실을 알릴 뿐이다.
범주 제외(혼합물·펩타이드·고분자·계면활성제·자외선차단제)만 막는다.

## 2. 출력 — 있는데 안 보이던 것을 꺼내고, 그림을 붙였다

### 새 열과 배너

| 추가 | 실측값 (프로테옴 실행) |
|---|---|
| `순위 편차` 열 (방법별 순위 최댓값−최솟값) | 상위 50 중앙값 **201위** |
| `진입 경로` 열 | AutoDock 269 / DiffDock 97, **상위 50에는 DiffDock 경로 0개** |
| 격자 커버리지 배너 | 13,339 / 15,038 = **88.7%** |
| 방법별 순위 4열 (CSV) | `:147`에서 수집만 하고 버리던 값 |
| pose 출처 (`scored_actual_docked_pose`, `gpu_enabled`) | 표적 상세 |

### 그림 3종 (인라인 SVG, JS 라이브러리 없음)

1. **방법마다 순위가 얼마나 갈리나** — 표적별로 최고 순위와 최저 순위를 잇는 선.
   50개 전부 선이 길다. "근거 수 4"가 합의가 아니라는 것을 한 장으로 보여준다.
2. **이 표적들은 전체에서 어디쯤인가** — 채점된 13,339개의 ΔG 분포 위에 표에 실린
   50개를 표시. 상위권이 왼쪽 꼬리에 몰려 있는지 눈으로 확인된다.
3. **근거가 얼마나 가까운가** — Daina 경로의 최근접 유사도 분포와 0.6 기준선.

Plotly는 쓰지 않았다. 4.6 MB의 JS를, 압축해서 이메일로 보내라고 안내하는 폴더에
넣을 이유가 없다. matplotlib으로 서버에서 그려 SVG를 인라인한다.

**한글 문제**: matplotlib은 글자를 기본적으로 **글리프 path**로 그리는데 번들 폰트
(DejaVu)에 한글이 없어 축 레이블이 통째로 사라졌다. `svg.fonttype="none"`으로
`<text>` 요소를 쓰게 하고 페이지의 폰트 스택을 지정해 브라우저가 그리게 했다.
부수 효과로 index.html이 184 KB → 120 KB로 줄었다.

## 3. 3D — Workbench 안에서 바로 본다

뷰어는 실행마다 자동 생성되고 있었지만 **UI 어디에서도 링크되지 않았다**
(`grep -rn "viewer" workbench/` → 0건). 결과 화면 안에 iframe으로 넣었다.

브라우저 검사가 잡은 결함 세 가지 — 정적 검사로는 전부 통과하는 것들이다:

| 증상 | 원인 | 수정 |
|---|---|---|
| 프레임이 아예 뜨지 않음 | Workbench CSP가 `default-src 'none'`이고 `frame-src`가 없어 fallback으로 차단 | `frame-src 'self'` 추가 |
| 프레임은 뜨는데 3D가 빈 화면 | Mol*가 WASM을 `data:` URI로 가져오는데 `connect-src 'self'`가 차단 | 뷰어 응답에 한해 `connect-src 'self' data: blob:` |
| 뷰어 안에서 이동하면 5초 뒤 첫 화면으로 돌아감 | 폴링이 `innerHTML`을 다시 쓰면서 iframe을 재생성. iframe은 DOM에서 옮기기만 해도 브라우저가 다시 로드한다 | 뷰어 섹션을 폴링이 건드리지 않는 별도 컨테이너로 분리 |

`unsafe-inline`은 끝내 쓰지 않았다. 뷰어의 인라인 `<script>`를 번들 자산
(`assets/sort.js`, `assets/target.js`)으로 옮겨 해결했다. `file://`에서는
같은 폴더의 `<script src>`가 허용되므로 오프라인 동작도 그대로다.

최종 브라우저 실측: 콘솔 에러 0, trajectory 2개(수용체 2,085원자 + pose 24원자),
canvas 1개, fallback 숨김.

## 4. 다운로드 — 이제 실제로 받아진다

이전에는 **모든 아티팩트 행이 `등록 필요`** 였다. `_artifact_rows`가
`status: "unregistered", download_url: None`을 하드코딩했고, 등록은 coordinator의
promote API가 해야 하는데 **프로덕션 코드 중 그걸 부르는 것이 없다**.

런 디렉터리에서 직접 서빙하는 경로를 추가했다. 등록된 아티팩트가 있으면 그것을 쓰고,
없으면 파일로 폴백한다.

격리 조건 — 등록 경로와 동일하게:
- 절대경로·`..`·역슬래시 거부
- `resolve()` 후 런 디렉터리 containment 검증 (심볼릭 링크 탈출 차단)
- **확장자 화이트리스트** (json/md/csv/tsv/log/txt/html/css/js/pdb/sdf/pdbqt)

실측: `ethanol_target_fast_full`의 아티팩트 21개 전부 다운로드 가능,
경로 탈출 3종 모두 404.

버튼 3개를 붙였다 — 전체 zip(판정 + 검증 + 뷰어 폴더), 순위표 CSV, 판정 보고서.

## 5. 접속 — 인증을 넣고 원격 바인드를 열었다

이전: `--host 0.0.0.0`은 서버가 **아예 거부**했고, 그래서 SSH 터널이 유일한 길이었다.
동시에 **모든 GET이 무인증**이었다(`do_GET`의 첫 줄이 `urlsplit`).

지금:

| 바인드 | 인증 | 결과 |
|---|---|---|
| loopback | 꺼짐 (기본) | 기존과 동일 — 로컬 단독 사용자 흐름 그대로 |
| loopback + `--require-auth` | 켜짐 | 로그인 필요 |
| non-loopback | **자동으로 켜짐** | 로그인 필요 |
| non-loopback + `require_auth=False` | — | **시작 거부** |

실수로 무인증 노출이 생기지 않는 것이 설계의 핵심이다.

- 접속 토큰: `~/.local/share/skinscout/secrets/workbench-access.token`,
  0600 강제, `O_NOFOLLOW`, 상수시간 비교 (worker 토큰과 같은 패턴)
- `POST /api/session`으로 토큰 → HttpOnly · SameSite=Strict 세션 쿠키(12시간)
- 인증이 켜지면 `/`, `/assets/*`, `/api/identity`, `/api/session`만 열려 있다.
  로그인 화면을 그리는 데 필요한 최소한이다
- 틀린 토큰과 없는 토큰의 응답이 동일하다(401, 같은 문구)

브라우저 실측: 게이트 표시 → 틀린 토큰은 문구만 바뀌고 게이트 유지 → 맞는 토큰
입력 시 게이트 사라지고 실행 43개 로드, 콘솔 에러 0.

**남는 한계**: 통신은 암호화되지 않은 HTTP다. 신뢰된 사내망 전제이며,
인터넷 노출이 필요하면 앞단에 HTTPS 리버스 프록시가 필요하다. README에 명시했다.

## 6. 그 밖에

- **진행률**이 실제 산출물 기준으로 바뀌었다. 판정할 산출물이 없으면
  "아직 단계를 판정할 산출물이 없습니다"라고 말하고 아무 단계도 칠하지 않는다
- **필터를 걸어도 전체 순위가 유지된다**. `rank`(전체)와 `filtered_position`(이 목록)
  을 분리했고, 5초 폴링이 정렬·필터를 되돌리지 않는다
- **뷰어 생성 실패가 기록된다**. 이전에는 stderr로만 나가 48 KB 로그에 묻혔다.
  이제 `run_viewer_status.json`에 남고 결과 화면이 이유를 보여준다
