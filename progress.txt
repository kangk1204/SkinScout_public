- **`os.environ[...]` inside bash heredocs requires `export`** before the
  here-doc (fixed in mirror_chembl.sh / mirror_drugbank.sh / mmseqs_build.sh).
- **Defer rdkit imports** inside script functions so pure helpers (classify,
  decide, apply_skin_weight, etc.) stay unit-testable in lean Python envs
  without RDKit installed.
- **AlphaFold DB URL pattern**: `/latest/UP000005640_9606_HUMAN_v4.tar` is now
  404; correct path is `/v4/...`. Both config + script updated.
- **Snakemake rule cross-reference**: `rules.<other>.output.foo` requires the
  rule file to be `include:`-ed *before* any rule that references it. The
  top-level Snakefile orders includes from Stage 0 → 11.
- **Host hardware** (RTX 3080 Ti 12 GB / 16 cores) is below the §intro spec
  (16 GB / 32 cores). README + ARCHITECTURE flag this; `config.yaml` carries
  `pocket_crop_radius=20.0` and `boltz2_max_residues=700` to make Stage 5/6
  fit.

## 2026-05-24 — ChEMBL 쿼리 근본 수정 (2개 원인)

원인 1 — 느린 쿼리: ChEMBL34 sqlite에 assays.tid 인덱스 부재 →
  target_dictionary→assays 조인이 1.6M행 full SCAN(nested-loop) → 수 시간 정체.
  EXPLAIN에서 `SCAN a` 확인. 다른 테이블(td/tc/cs)은 인덱스 탐.
  수정: CREATE INDEX idx_assays_tid ON assays(tid) — 생성 1.5초, 로컬 미러라 영구.
  결과: target→assays 조인 338,048행 0.30초, EXPLAIN `SEARCH a USING idx_assays_tid`.
  스크립트(stage0_mirror_chembl.sh)에 인덱스 자동 보장 로직 추가 (신규 DB 대비).
  ※주의: 지난 "정체" 진단 중 일부는 내 진단 reader가 read lock을 잡아 인덱스 생성을
    차단("database is locked")한 것 — 인덱스 자체 생성은 1.5초로 빠름.

원인 2 — pyarrow OverflowError("Python int too large to convert to C long"):
  ChEMBL standard_value에 2^63 초과 거대값 → int64 추론 실패, 53MB까지 쓰고 크래시.
  수정: 고정 pa.schema(act_value/pchembl=float64, 나머지 string) +
    pd.to_numeric(errors='coerce') 강제 변환. 모든 청크가 단일 스키마 공유.

진단 교훈: python print가 파일 리다이렉트 시 버퍼링 → "무출력=정체"로 오인. -u + flush 사용.
